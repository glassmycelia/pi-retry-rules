# pi-retry-rules

[English](../../../README.md) · [简体中文](README.md)

重新尝试失败的 pi 模型请求，不添加“继续”指令，也不把失败回复或部分输出重新发给模型。

- **自动重试**：按供应商、可选模型及错误文本匹配，将错误交给 pi 原生重试机制。
- **`/retry`**：手动触发一次请求，不新增永久规则或独立重试循环。
- **`/retry-rules`**：在 pi 内管理规则、语言、配置路径及原生重试参数。
- 仅在重试期间显示“重试中（第 1/3 次）”或“手动重试中（第 1/1 次）”；成功、失败或取消后清除，不再常驻显示规则数量。
- 原始错误保留在历史中，但通过上下文排除记录避免再次发送给模型。
- 保留已经完成的工具结果，不由重试机制自动重放工具。
- 无额外运行时依赖，不修改 pi 内核或私有方法。

## 安装

当前验证版本为 **pi 1.5.0**；需要 Node.js **22.19.0 或更新版本**，由 pi 提供 `@earendil-works` 宿主包。本版本不支持旧 pi API。

将项目复制或克隆到目标机器后：

```bash
pi install /path/to/pi-retry-rules
```

本地安装直接引用目录，不复制文件。安装或源码更新后，在已有 pi 对话执行 `/reload`。临时加载、不写入扩展包列表：

```bash
pi -e /path/to/pi-retry-rules/index.js
```

普通使用不必安装开发依赖。直接安装 GitHub 标签版本：

```bash
pi install git:github.com/glassmycelia/pi-retry-rules@v0.4.1
```

固定标签或提交便于复现。安装时加 `--local` 可限制到受信任项目。本项目通过 GitHub 分发，无需 npm 发布。不要同时加载另一个注册 `/retry` 的扩展。

## 指令

### `/retry`

仅在 pi 空闲且最后一条模型对话是助手错误时，从错误前的有效上下文重新请求。成功回复、取消回复、空会话和忙碌会话不触发。

隐藏控制消息仅用于启动请求，会在发往模型前被过滤；首次重试完成后，它和旧失败回复通过 `context_edit` 持久排除。原始历史仍可查看，不增加用户指令。

**“单次”表示手动触发一次，不是整个过程最多一个 HTTP 请求。** 已启用的 pi 自动重试、供应商重试和正常工具循环继续有效。手动指令不创建临时自动规则；后续错误命中已有策略时仍可能自动重试。模型也可能主动再次调用工具，本扩展不保证工具幂等性。

### `/retry-rules`

在支持扩展对话框的 TUI 或 RPC 客户端打开菜单：

| 菜单 | 作用 |
| --- | --- |
| 开启／关闭自动规则 | 只控制本扩展的额外重试判定，不替代 pi 原生开关 |
| 新增／编辑／删除规则 | 编辑供应商 ID、可选模型 ID 和匹配文本 |
| 编辑完整配置 JSON | 编辑全部扩展设置；确认后修复无效配置 |
| 配置文件路径 | 选择或创建本会话使用的规则文件 |
| pi 原生重试参数 | 编辑原生次数、退避和供应商超时／重试设置 |
| 语言 | 切换 English／简体中文 |
| 查看配置 | 查看路径、规则和当前生效的原生参数 |
| 重新读取配置 | 读取外部编辑结果，无需重启 pi |

规则和语言保存后立即生效。原生参数保存到个人 `settings.json` 或受信任项目 `.pi/settings.json`，需要确认并自动请求重载。其他字段保持不变，项目设置可能覆盖个人设置。原生参数影响 pi 自身和其他使用原生调度的扩展。

## 配置位置和语言

默认文件为：

```text
<Pi agent directory>/pi-retry-rules.json
```

通常是 `~/.pi/agent/pi-retry-rules.json`，遵守 `PI_CODING_AGENT_DIR` 覆盖。**实际配置不在扩展安装目录中，不进入 Git 或发布包**，升级扩展不会恢复默认规则。

不存在文件时，使用以下内存默认值，只有用户保存时才创建文件：

```json
{
  "enabled": false,
  "language": "en",
  "rules": []
}
```

`language` 支持 `en`、`zh-CN`，旧配置缺少该字段时使用英文。它控制扩展菜单、通知和状态，不改变 pi 自身界面、供应商错误、指令名称或用户匹配文本；命令发现描述保持英文。不自动检测系统语言。

通用规则示例：

```json
{
  "enabled": true,
  "language": "zh-CN",
  "rules": [
    {
      "provider": "example-gateway",
      "model": "example-model",
      "contains": ["API error (400)", "temporary upstream rejection"]
    }
  ]
}
```

- `provider` 是 pi 的连接标识，不一定是模型厂商，必须填写。
- `model` 匹配模型 **ID**，不是显示名称；省略表示该供应商的所有模型。
- `contains` 区分大小写，一条规则中全部文本都需包含；不同规则任意一条命中即可。
- 不支持供应商通配或正则。
- 不重新分类取消、认证／权限错误、上下文超限；额度／账单等致命排除仍由 pi 判定。
- 无效配置停用额外自动规则，不静默覆盖；修复需在完整 JSON 编辑器确认。

启动时指定其他文件：

```bash
pi --retry-rules-config /path/to/private-rules.json
```

需先加载扩展，也可与 `-e` 组合。菜单选择的路径保存在当前分支元数据中，恢复、重载和树导航后保留；新会话使用启动参数或默认位置。不要把凭据、个人标识和整段对话复制成规则，也不要提交实际配置。

## pi 原生参数

菜单编辑的是 pi 的 `retry` 设置，不另存一套调度参数：

```json
{
  "enabled": true,
  "maxRetries": 3,
  "baseDelayMs": 2000,
  "maxAgentDelayMs": 60000,
  "provider": {
    "maxRetries": 0,
    "maxRetryDelayMs": 60000
  }
}
```

次数为非负整数，延迟／超时单位毫秒，菜单接受 `0～2147483647`。`provider.timeoutMs` 可选，删除可清除选定范围内的配置并继承 pi 相应超时；`0` 关闭该超时。供应商层重试建议保持 `0`，除非确实需要，避免嵌套重试放大请求次数。

## 原理和边界

自动规则在 `message_end` 保留错误并追加明确的本地重试提示，由 pi 负责退避、取消、计数和持久上下文排除。它依赖当前错误分类器，升级 pi 后需重新测试。

手动入口只使用公开的 `sendMessage`、上下文和请求结束钩子，不缓存原始 HTTP 包。新请求由 pi 重新构造，其他扩展、路由、压缩或配置改变都可能影响请求内容。

配置验证后才替换，扩展并发保存使用锁并检测外部修改。若进程保存中崩溃，可能留下 `<config>.lock`，确认没有会话保存后才清理。原生设置采用 pi 的锁目录约定。无效现有文件不自动覆盖。
